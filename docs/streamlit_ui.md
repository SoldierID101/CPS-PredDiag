# Streamlit UI v0.1 — исследовательский интерфейс CPS-PredDiag

## Назначение

Локальный интерфейс для **исторического воспроизведения** реальных эпизодов
**класса 2** Petrobras 3W v2.0.0. В интерфейсе нет управляющих команд,
производственного мониторинга и подключения к старой базе данных.

## Подготовка

Из корня проекта (Windows PowerShell, активирована `.venv`):

```powershell
python -m pip install -r requirements-ui.txt
python -m unittest discover -s tests -v
python -m streamlit run streamlit_app.py
```

Ожидаемые пути:

- `dataset/2/WELL-*.parquet` — реальные временные ряды класса 2;
- `outputs/models/class2_prototype/manifest.json` и файл модели, указанный в manifest;
- `rules/class2_dhsv.json` — текущий проектный JSON с пустым набором неутверждённых правил.

Новая Streamlit-страница доступна по адресу, который покажет команда запуска
(обычно `http://localhost:8501`).

## Работа

1. Выбрать реальный эпизод скважины.
2. Выбрать `blind` (нет доступа к меткам события) или `oracle_replay`
   (истинные прошлые метки `102` используются ТОЛЬКО для исследовательского
   подтверждения переходной фазы).
3. Установить шаг диагностики, по умолчанию **300 секунд**; `0` в максимуме
   точек означает воспроизведение полного эпизода.
4. Нажать «Запустить диагностику».
5. Смотреть временную шкалу некалиброванной ML-оценки, графики телеметрии,
   таблицу решений и объяснения для выбранного времени.

Результаты каждого запуска сохраняются по пути:

```text
outputs/pipeline_replay/<mode>/<имя_файла_без_расширения>/
    decisions.jsonl
    timeline.csv
    summary.json
```

Разные эпизоды и режимы не перезаписывают друг друга, но **повторный запуск
того же эпизода в том же режиме перезапишет его три файла**. Не следует
считать повторные запуски неизменяемым журналом аудита.

## Ограничения

- Исследовательская версия, не промышленная система безопасности.
- Класс `102` в oracle-режиме — **истинная разметка**. Это не независимый
  детектор и не измерение качества диагностики.
- В blind ML Agent не выдаёт прогноз, пока нет независимого подтверждения `102`.
- Некалиброванная оценка модели не трактуется как вероятность физического отказа.
- `rule_based_agent.py` и `prognostic_agent.py` пока не получили утверждённых
  физических порогов. `unknown` — ожидаемое честное заключение Coordinator.
- Порог `0,5` — исследовательская отсечка ML, а не физическая граница отказа.
- На графиках телеметрии отображаются поминутные медианы **только для
  визуализации**; агентам передаются исходные секундные измерения.
- Интерфейс работает с `dataset/2/WELL-*.parquet`, другие классы не поддерживает.
- Для корректной оценки эффективности требуются независимая проверка по
  скважинам и сопоставление с фактическим моментом события.

## Технические принципы

Streamlit вызывает существующие `DiagnosticPipeline`, `replay_pipeline`,
`write_replay_outputs` и не дублирует внутренние правила принятия решений.
Никакие численные диагностические пороги не создаются в UI. Измерения и
полные результаты сохраняются локально, PostgreSQL не используется.
