# CPS-PredDiag — проверка hard negatives для прогноза DHSV (v0.1)

**Статус:** эксперимент готов к запуску на пользовательских файлах Petrobras. Результатов улучшения на реальном датасете **ещё нет**. Скрипт не изменяет `ml_agent.py`, интерфейс, правила или БД.

## Зачем эксперимент

На горизонте 30 минут CatBoost-12 обнаруживал **9 из 11** завершённых эпизодов класса 2 в исследовательской Leave-One-Well-Out проверке. Но последующий стресс-тест 96 контрольных файлов показал частые и длительные ложные срабатывания на нормальной работе и других типах нежелательных событий. Цель: сравнить **одинаковые CatBoost-12** с разными обучающими примерами:

- `baseline`: только 503 окна ранее сформированной когорты класса 2 (66 положительных).
- `hard_negative`: та же когорта + **ограниченная детерминированная выборка** отрицательных окон класса 0 и других событий, в которых класс 2 отсутствует на всём 30-минутном будущем горизонте.

В обоих вариантах: исходные 12 признаков, CatBoost (300 итераций), горизонт 30 минут, пороги 0,5 и 1/2 последовательных подтверждения. `class`, `state`, идентификатор скважины и будущее **не передаются в признаки**. Отрицательная разметка применяется при **подготовке обучающей выборки и оценке**, а не для гейтинга модели в момент прогноза.

## Входы

Существующие файлы пользователя (не включать датасет в Git):

- `outputs/class2_horizons/cohort_features.csv` — ранее рассчитанные класc2 окна всех горизонтов; берётся только горизонт 30 мин.
- `outputs/class2_specificity/selected_files.csv` — фиксированный набор 96 контрольных Parquet (прежде выбранный без просмотра ML-оценок).
- `dataset/{0,1,3,4,5,6,7,8,9}/WELL-*.parquet` — исходные реальные записи. Нужны только файлы из `selected_files.csv`.
- Существующие Python-модули: `experiments/blind_class2_forecast.py`, `experiments/evaluate_class2_controls.py`, `experiments/evaluate_class2_alert_policy.py`, `ml_agent.py`.

## Разделение по скважинам без утечки

1. **DHSV-эпизоды**: внешний Leave-One-Well-Out по семи скважинам. При тестировании WELL-X **все** записи WELL-X исключаются из обучения обоих вариантов модели, включая контрольные файлы иных классов.
2. **Контрольные скважины, у которых нет DHSV-событий в этой когорте**: разделяются по стабильному SHA-256 от ID скважины (соль зафиксирована в скрипте), примерно 30% целиком удерживаются от обучения. Разделение только по ID скважины и не зависит от предсказаний или меток.
3. В обучении hard-negative варианта используются только контроли из *разрешённых обучающих* скважин (и контрольные записи других тренировочных DHSV-скважин). На каждый файл берётся не более 12 окон, на сочетание «скважина/класс» не более 24. Выбор окон равномерно по их временному порядку, **без просмотра score**.
4. Внешний DHSV-LOOW тест и тест на **полностью удержанных контрольных скважинах** считаются **отдельно**. Внешние контроли оцениваются моделью, обученной на всех семи DHSV-скважинах, но без удержанных контрольных скважин.
5. Параметры CatBoost и политика 0,5 / 1–2 подтверждения фиксированы заранее. **Вложенный подбор порога здесь намеренно не проводится**, поскольку после добавления hard negatives распределение оценок меняется.

Это строгая изоляция внутри **текущего эксперимента**, но **не чистый окончательный тест**: файлы, классы, горизонты и признаки уже исследовались в проекте. Следовательно, результат остаётся предварительным.

## Как запустить (Windows / VS Code)

Из корня `D:\CPS-PredDiag`, с активной `.venv`:

```powershell
python -m unittest discover -s tests -v
python experiments/evaluate_class2_hard_negatives.py
```

Для короткой синтетической проверки только новых тестов:

```powershell
python -m unittest discover -s tests -p 'test_class2_hard_negatives.py' -v
```

Если структура папок отличается, у скрипта есть `--training`, `--selected`, `--dataset`, `--output`.

### Критерий исследовательского улучшения

Результат положительный, **если** количество DHSV-эпизодов, обнаруженных на внешних LOOW-скважинах, сохраняется близким к 9/11, а на **удержанных** контрольных скважинах заметно падает **доля времени с ложной активной тревогой**. Одно лишь сокращение числа *начал* тревог недостаточно: непрерывная ложная тревога тоже проблема. Не выбирать победителя только по F1 или AP на событийной когорте.

### Ограничения

- Это не промышленная точность/реальная false-alarm rate: контрольные файлы отобраны, а не представляют все часы эксплуатации.
- Примеры других отказов «отрицательны» **только относительно события класса 2**, а не означают исправность скважины.
- Внутри группы контроля много коррелированных 5-минутных окон; небольшое число независимых скважин и DHSV-эпизодов.
- При реальном использовании нет доступа к истинной метке будущего или текущего события для отбора окон. Здесь разметка нужна только для ретроспективной оценки.
- Числовой score CatBoost не является калиброванной вероятностью физического отказа.
- Улучшения и статистическая значимость **не гарантированы**, прежде чем смотреть результаты, нельзя утверждать достижение 80–90%.
