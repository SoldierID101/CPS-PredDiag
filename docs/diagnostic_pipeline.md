# Диагностический конвейер CPS-PredDiag v0.1

Статус: **исследовательский прототип**, без БД и команд оборудованию.

## Назначение

`diagnostic_pipeline.py` передаёт один временной срез телеметрии в:

1. `RuleBasedAgent.evaluate(snapshot)` — правила по текущим значениям;
2. `PrognosticAgent.predict(history)` — экстраполяция до документированных порогов;
3. `MLAgent.predict(history, transition_102_confirmed=...)` — исследовательская оценка события класса 2 на горизонте 15 минут;
4. `coordinate_decision()` — совместное заключение;
5. `generate_explanation()` — текстовое объяснение.

При пустых `rules/class2_dhsv.json` и конфигурации порогов `PrognosticAgent()` итоговый уровень обычно **`unknown`**, а не `normal`.

## Режимы

| Режим | Использование `class` | ML Agent | Для чего пригоден |
|---|---|---|---|
| `blind` (по умолчанию) | Не используется; поле удаляется до агентов | `not_applicable`, пока нет независимого подтверждения 102 | Проверка честного поведения без oracle |
| `oracle_replay` | Только прошлая разметка 300-секундного окна класса 102 | Применяется при выполнении условия | Демонстрация интеграции; **не** независимая валидация |

В обоих режимах поля `class`, `state`, `target`, `label`, `event_class`, `target_h15` удаляются из входных данных всех аналитических агентов. Все строки после `decision_time` отбрасываются.

**Особо:** опубликованные результаты LOOW для ML Agent не являются результатами текущего pipeline. Модель в `outputs/models/class2_prototype` обучена на всех 253 доступных размеченных окнах; повторная проверка этой же моделью на исходных скважинах не даёт независимой оценки качества.

## Запуск из корня проекта

Убедиться, что на месте `ml_agent.py`, `rule_based_agent.py`, `prognostic_agent.py`, `coordinator.py`, `explanation.py`, `rule_config.py`, модель и `rules/class2_dhsv.json`.

```powershell
python -m unittest discover -s tests -v

# Слепой режим: последнее измерение в указанном эпизоде
python experiments/run_pipeline_once.py --file dataset/2/WELL-00002_20131104004101.parquet

# Демонстрация: первое полное 300-секундное окно перехода 102
python experiments/run_pipeline_once.py --file dataset/2/WELL-00002_20131104004101.parquet --mode oracle_replay
```

Скрипт сохраняет результат в `outputs/pipeline_runs/one_window.json` (локальный файл, не БД). Следите, чтобы результаты `blind` и `oracle_replay` не сравнивались как независимые эксперименты.

В `oracle_replay` момент выбирается по истинной разметке, поэтому этот режим **не подходит для измерения качества детекции события**.

## Ограничения

- Модель выдаёт некалиброванную оценку, а не достоверную вероятность физического отказа.
- Прогноз достижения инженерного порога не равен прогнозу времени отказа.
- Отсутствие действующих правил и порогов не означает исправность оборудования.
- Запуск pipeline на исходных данных пока проверяет интеграцию, а не точность диагностики.
- Выбор режима `oracle_replay` требует явного указания пользователя и остаётся только исследовательским.
- Не поддерживаются фоновые автоматические действия, сохранение в PostgreSQL, онлайн-управление скважиной.
