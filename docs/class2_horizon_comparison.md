# CPS-PredDiag: сравнение горизонтов прогноза класса 2

**Протокол v0.1, 05.11.2026.** Статус: *запланирован и протестирован на синтетических данных; результаты Petrobras ещё не получены*.

## Исследовательский вопрос

Улучшит ли переход с 15-минутного горизонта к 30 или 60 минутам раннее предупреждение о **первом наблюдаемом наступлении `class=2`** (закрытие DHSV) при использовании одной и той же модели CatBoost и одинаковой прошлой телеметрии?

Предыдущий эксперимент `blind_class2_forecast.py` показал для CatBoost-12 (15 мин) на 536 окнах и 11 завершённых эпизодах: AP=0,3158; F1@0,5=0,2906; 8/11 обнаруженных событий; 67 ложноположительных окон. **Это контрольная точка, а не прогноз новых результатов.**

## Протокол

| Компонент | Решение |
|---|---|
| Данные | `dataset/2/WELL-*.parquet`, только real WELL, класс 2, без SIMULATED/DRAWN |
| Моменты диагностики | Каждые 300 секунд после 900 секунд непрерывной истории; от меток событий расписание не зависит |
| Вход | 12 признаков по 300 секундам для `P-MON-CKP`, `P-TPT`, `T-TPT`: mean, std, delta, slope_per_hour |
| Горизонты | 15, 30, 60 минут — **заданы до запуска** |
| Цель | `1`, если `class=2` впервые наблюдается в `(t, t+H]` и разметка до события известна; `0`, если все H секунд будущего известны и `class=2` отсутствует |
| Неизвестное будущее | Исключить как цензуру; **не** считать отрицательным |
| Точки после первого события | Не включать в выборку для задачи первого наступления, только при *ретроспективной оценке* |
| Модель | CatBoostClassifier, 300 деревьев, depth=4, lr=0.03, l2=5, class weights Balanced, nan_mode=Min, seed=42 |
| Валидация | Leave-One-Well-Out: целиком исключаем одну скважину для теста |
| Порог тревоги | Фиксированный 0,5, без подбора по контрольным скважинам; **не калиброванная вероятность** |
| Главные итоги | Количество обнаруженных эпизодов, медианная заблаговременность, окна с ложными сигналами, приближённое количество серий ложных сигналов |
| Вспомогательные | Precision, Recall, F1, AP, доля положительных и число пригодных окон |

Скрипт повторно использует функции разметки и извлечения признаков из `experiments/blind_class2_forecast.py`; действующие `ml_agent.py`, `diagnostic_pipeline.py` и Streamlit не меняются.

## Важные методологические оговорки

1. **Разные горизонты — разные целевые переменные.** С увеличением горизонта меняется число положительных окон и, из-за цензуры, состав оценочной выборки. Поэтому более высокий AP/F1/Recall нельзя автоматически считать повышением точности одного и того же задания.
2. Отдельный файл `comparison_common_times.csv` оценивает прогнозы в пересечении моментов, пригодных для всех трёх горизонтов; метки `target` при этом всё равно разные.
3. **Без oracle-гейта** означает, что `class=102` не используется для выбора момента запуска и не передаётся модели. Но истинная разметка необходима для обучения, целевых меток и ретроспективного определения интервалов до первого события. Это **не полноценное онлайн-тестирование**.
4. Выбраны записи с классом 2, то есть датасет **обогащён событиями**. Частота ложных окон на час пригодных отрицательных наблюдений не равна частоте ложных тревог на час обычной эксплуатации.
5. Наблюдения соседних окон коррелируют; 7 скважин и 11 событий — мало для уверенных выводов.
6. Эти скважины и признаки уже исследовались. Если по итогам эксперимента выбирается горизонт, его преимущества нельзя объявлять независимо доказанными на этих же тестовых скважинах. Для будущей честной оценки нужны вложенный выбор на обучающих скважинах и новые удержанные эпизоды или независимый датасет.
7. В отчёте `fp_alert_clusters_approx` учитывает соседние ложноположительные *окна* как одну серию (если разрыв более 5 минут — новая серия). Это упрощённый показатель, не полноценная производственная система тревог.
8. Время события — наблюдаемое начало `class=2`, а не обязательно момент физического отказа; корректность разметки и полноту датчиков учитываем как ограничения.

## Как запустить

Из корня `D:\CPS-PredDiag`, с активированной `.venv`:

```powershell
python -m unittest discover -s tests -v
python experiments/compare_class2_horizons.py
```

Скрипт не меняет исходные файлы и сохраняет результаты отдельно в `outputs/class2_horizons/`. В `--max-files` можно уменьшить количество файлов для отладки, но **не делать научных выводов** по неполному набору.

## До запуска и после

**До запуска:** неизвестно, какой горизонт даст лучший результат; никакие улучшения не заявлены.

**После запуска:** сначала проверяем число положительных окон, количество доступных завершённых эпизодов и цензуру для каждого горизонта. Затем анализируем по скважинам и по эпизодам. Выбор «победителя» не производим исключительно по максимальному AP/F1 в этой исследовательской оценке.
