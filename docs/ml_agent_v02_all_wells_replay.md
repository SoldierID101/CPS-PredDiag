# Multi-WELL offline replay — ML Agent v0.2

**Версия:** 0.1, 06.11.2026. **Статус:** техническая проверка воспроизводимости, не новая независимая валидация ML-качества.

## Цель

Проверить, что отдельный `ShadowMLAgentV02` воспроизводит ранее сохранённые LOOW-прогнозы исследовательской CatBoost-12 на **всех доступных файлах** класса 2 Petrobras 3W Dataset v2.0.0. Для каждой тестовой скважины модель переобучается один раз на остальных скважинах, затем последовательно обрабатываются все её файлы. Ни `Coordinator`, ни `Streamlit` не изменяются.

## Зафиксированная конфигурация

- История для допуска к расчёту: 900 секунд; признаки по последним 300 секундам.
- Решение каждые 300 секунд, начиная с завершения необходимой истории в каждом непрерывном участке.
- 12 исходных признаков `P-MON-CKP`, `P-TPT`, `T-TPT`: mean/std/delta/slope.
- Горизонт 30 минут; CatBoost 300 итераций; Hard Negative ratio = 0 (исторический baseline).
- Порог 0,5; одно последовательное подтверждение.
- Полный запрет oracle-гейта: `class`, `state` удаляются до вычисления признаков.
- Новый экземпляр shadow-агента/сброс состояния для **каждого файла**.
- Сопоставление признаков, CatBoost-оценки и `alert_active` выполняется **только на точках, сохранённых в исторической допустимой когорте**.

## Источники и разделение

- `outputs/class2_horizons/cohort_features.csv` — сохранённая когорта (используется для выбора LOOW-обучения и набора сравнимых моментов).
- `outputs/class2_hard_negative_balance/class2_scores_and_alerts.csv` — архивные оценки; выбирается `ratio=0`, `policy=fixed05_1` для соответствующего `outer_well`.
- `dataset/2/*.parquet` — реальные исходные сенсоры класса 2.

**Ожидаемый инвентарь по предоставленному архиву**: 22 файла / 7 скважин / 503 сравнимых решения. Это ожидаемый размер при неизменных CSV, **не измеренный итог запуска нового сценария на Windows**.

При LOOW исключается *вся* тестовая скважина, включая другие файлы. Модель один раз обучается для внешней скважины и повторно используется для всех её файлов. Никакие метки тестовой скважины не передаются в обучение или модель при replay.

## Команды

```powershell
cd D:\CPS-PredDiag
python -m unittest discover -s tests -p "test_offline_replay_ml_v02_all.py" -v
python -m unittest discover -s tests -q
python experiments/offline_replay_ml_v02_all.py
```

Выходная папка: `outputs/ml_agent_v02_replay_all_wells/`:

- `all_wells_replay_summary.json` — общий результат, ожидаемые/проверенные файлы и решения, SHA-256 входных файлов, версии ПО.
- `file_parity.csv` — одна строка на исходный Parquet; ошибки, паритет признаков/оценок/тревог.
- `well_parity.csv` — отдельная сводка по каждой тестовой скважине.
- `WELL-..._replay.csv` — детальный след вычислений (никаких истинных целей или меток качества в этих трассировках).

Если любого файла не хватает, сценарий **не начинает** вычисления. Если один файл даёт ошибку или несовпадение, сценарий продолжает проверять остальные, записывает отчёт и завершает работу с ошибкой. `parity_pass=true` допустим только при совпадении всех сравнимых решений во всех файлах и полном соответствии числа файлов, скважин и точек.

## Как интерпретировать

Совпадение подтвердит перенос исследовательского алгоритма в новый интерфейс ML Agent; **не докажет** качество прогнозирования на независимых данных. Контроль вне ретроспективной когорты остаётся непроверяемым с точки зрения истинного отрицательного исхода. Эти дополнительные решения нельзя суммировать с false-positive, оценивать как промышленные часы работы или пересчитывать F1/PR-AUC без новой разметки. Эталонные оценки уже были исследованы в предыдущих экспериментах.

Не делайте выбор порога, доли hard negatives или состава признаков по результатам этого технического replay.
