# Последовательное воспроизведение Petrobras 3W: CPS-PredDiag

**Версия:** 0.1. **Статус:** исследовательский функциональный прототип.

## Назначение

`experiments/replay_pipeline.py` запускает существующий `DiagnosticPipeline`
на нескольких последовательных точках **одного реального Parquet-файла класса 2**.
Первое решение принимается после 300 непрерывных секунд телеметрии.
Далее по умолчанию решения принимаются не чаще чем раз в 300 секунд.
Временной разрыв сбрасывает накопление окна.

Агенты получают только историю до рассматриваемой точки включительно.
Метки `class`, `state` и другие целевые признаки **не передаются аналитическим агентам**.

## Режимы

- **`blind`**: действительный диагностический сценарий без истинных меток; ML не
  активируется, пока нет независимого детектора переходного состояния 102.
- **`oracle_replay`**: для исследовательской демонстрации разрешено подтверждать
  состояние 102 по **прошлым 300 непрерывным меткам class=102**. Пропуски
  разметки (`pd.NA`) не подтверждают состояние. Это не независимый тест ML.

Без подтверждённых диагностических правил и порогов статус Coordinator обычно
будет `unknown`, а Prognostic не выдаст прогноз. Это корректно.

## Запуск из корня проекта

```powershell
python -m unittest discover -s tests -v
python experiments/replay_pipeline.py --file dataset/2/WELL-00002_20131104004101.parquet --mode blind
python experiments/replay_pipeline.py --file dataset/2/WELL-00002_20131104004101.parquet --mode oracle_replay
```

Для быстрой проверки можно ограничить число решений:

```powershell
python experiments/replay_pipeline.py --file dataset/2/WELL-00002_20131104004101.parquet --mode oracle_replay --max-points 10
```

По умолчанию результаты сохраняются отдельно для режимов в
`outputs/pipeline_replay/blind/` и `outputs/pipeline_replay/oracle_replay/`.
Повторный запуск **того же режима** перезаписывает его отчёты. Для нескольких
эпизодов указывать отдельную `--output-dir`.

## Формат результатов

- `decisions.jsonl`: полное заключение каждого момента, одна JSON-строка на решение;
- `timeline.csv`: компактная временная шкала, оценки модели и статусы агентов;
- `summary.json`: число решений, распределение статусов, количество oracle-подтверждений
  и экспериментальных сигналов ML.

**Нельзя интерпретировать** число предупреждений как число обнаруженных
неисправностей. Без независимого размеченного протокола не вычисляются
Precision/Recall, число предотвращённых отказов или эффективность мультиагентности.
Оценки ML некалиброваны; наличие поля `ml_score_uncalibrated` в CSV не означает
реальную вероятность отказа.

## Методологические ограничения

1. Обученный `MLAgent` относится только к классу 2 и горизонту 15 минут.
2. Реальный компонент подтверждения переходной фазы 102 ещё отсутствует.
3. Rule-Based и Prognostic пока не имеют научно подтверждённых порогов.
4. Решения в одном эпизоде статистически зависимы. Это функциональный replay,
   а не исследование качества на независимых скважинах.
5. Автоматического управления оборудованием и БД нет.
