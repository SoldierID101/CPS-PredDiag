# Эксперимент BLIND-CLASS2-001: прогноз перехода в класс 2 за 15 минут

**Статус:** протокол первого эксперимента, v0.1 (предварительный, не промышленная валидация)  
**Данные:** Petrobras 3W Dataset v2.0.0, реальные `WELL`-файлы из `dataset/2/`  
**Скрипт:** `experiments/blind_class2_forecast.py`  
**Нельзя путать с:** предыдущим `oracle_gated_class2_h15` (253 окна фазы `102`, AP CatBoost 0,3243).

## 1. Исследовательская цель

Проверить, улучшает ли CatBoost прогноз **наблюдаемого перехода разметки в класс 2** на горизонте 15 минут **без предварительного использования истинного класса `102`** в качестве входного признака или условия формирования признаков.

Это не обязательно момент физического начала отказа. В данных переходная фаза `102` описывает уже развивающееся нежелательное состояние, а класс `2` — размеченную следующую фазу. Задача *прогноза перехода в 2* отделена от задачи *раннего обнаружения отклонения от нормальной работы*.

## 2. Протокол формирования примеров

- Моменты решений: каждые **300 секунд** после накопления **900 секунд** непрерывной прошлой телеметрии; расписание не зависит от класса.
- Признаки: только измерения за 1, 5 и 15 минут **до решения, включительно**.
- Целевая переменная `y(t)=1`: первый наблюдаемый переход в `class=2` произошёл в `(t, t+15 мин]`, и весь предшествующий этому переходу отрезок имеет известные метки.
- `y(t)=0`: во всех следующих 900 секундах наблюдаются только известные `class=0/102`, перехода в 2 нет.
- **Цензура / неизвестная разметка**: если запись обрывается, содержит разрыв времени или неизвестную метку до истечения горизонта (либо до события), исход не классифицируется как 0 и исключается из обучения/оценки.
- **Ретроспективная risk-set**: для вычисления качества исключаются моменты после **первого наступления `class=2` в файле**, а также моменты с неизвестной текущей меткой. Этот фильтр необходим для определения научной задачи *до наступления события*, **но онлайн он недоступен и не должен использоваться для разрешения запуска модели**. Само расписание и извлечение признаков от метки не зависят.
- Датчики: базовые `P-MON-CKP`, `P-TPT`, `T-TPT` (не менее 2 с покрытием от 90% за последние 5 минут); дополнительно исследуется `P-PDG`. Если доступно меньше 2 базовых сигналов, расчёт признаков возможен, но вывод не включается в оценочную выборку.
- Не используются как признаки: `class`, `state`, `well_id`, `file`, время начала `102`, время до события, будущие данные.

**Ограничение:** все исходные файлы уже отобраны как эпизоды класса 2. Поэтому полученная частота тревог относится только к изученным *обогащённым событиями записям*, а не к любым скважинам при обычной эксплуатации.

## 3. Сравнение моделей при одинаковых условиях

| Модель | Признаки | Алгоритм |
|---|---|---|
| `rf_12` | 12 статистик трёх датчиков за 5 минут | Random Forest, 70 деревьев, `min_samples_leaf=5`, `balanced_subsample` |
| `catboost_12` | **Те же** 12 статистик | CatBoost, 300 итераций, глубина 4, learning rate 0,03 |
| `catboost_multiscale` | 60 заранее определённых признаков: 4 датчика × 3 окна × (среднее, std, delta, наклон, покрытие) | CatBoost с теми же гиперпараметрами |

Новые масштабы (1, 5, 15 мин) выбраны заранее по физическому смыслу и не подбираются по тестовым скважинам. 15-минутная **прошлая** история и 15-минутный **будущий** горизонт — разные интервалы.

Пропуски RF заполняются медианой, вычисленной **только на обучающих скважинах**; CatBoost использует свою обработку NaN. Обучение и проверка повторяются 7 раз по Leave-One-Well-Out (вся скважина удерживается целиком). Ни один идентификатор скважины не входит в `X`.

Гиперпараметры, признаки и порог `0.5` зафиксированы. **Подбора порога по контрольной скважине нет.** Изменять их по итогам этих 7 тестовых скважин и затем объявлять проверку независимой нельзя. Если улучшения появятся, потребуется отдельное подтверждение (например, новые скважины либо вложенная оценка изменений).

## 4. Метрики и ограничения интерпретации

Отчёты содержат:

- **AP (average precision)** и ROC-AUC по всем out-of-fold (OOF) окнам;
- Precision, Recall, F1 при фиксированном пороге 0,5;
- число ошибочных окон и приближённую частоту **FP-окон на час пригодных отрицательных окон**; этот показатель **не является** частотой ложных тревог на час реальной промышленной эксплуатации;
- число пригодных завершённых эпизодов и обнаружений (с первым предупреждением в пределах 15 мин до события), а также заблаговременность;
- расхождение метрик между скважинами, долю недоступных измерений и цензуру.

`eligible_completed_events` — только первые события файлов, у которых сформировано хотя бы одно положительное пригодное окно. Его необходимо сопоставить с `observed_class2_onsets` (исторически 11 завершённых эпизодов класса 2), а не считать автоматически равным всему числу событий.

**Целевой ориентир:** максимально приблизиться к 9/11 обнаруженным эпизодам (≈82%), при существенно меньшем числе ложных тревог. Достижение 80–90% по Precision/F1 не обещано, поскольку данных мало и измерения неоднородны. Accuracy не использовать как основную метрику.

## 5. Запуск

Из корневой папки `D:\CPS-PredDiag`:

```powershell
python -m pip install catboost pyarrow
python -m unittest discover -s tests -v
python experiments/blind_class2_forecast.py
```

Результаты появятся в `outputs/blind_class2/`:

| Файл | Что содержит |
|---|---|
| `cohort_audit.csv` | Сколько моментов просмотрено и почему окна исключены, по файлам |
| `cohort_features.csv` | Полная построенная когорта с признаками для воспроизводимости |
| `oof_predictions.csv` | Оценки трёх моделей на удержанных скважинах |
| `comparison.csv` | Основные метрики и обнаруженные события |
| `by_well.csv` | Метрики отдельно для каждой скважины |
| `by_event.csv` | Обнаружение каждого пригодного события и заблаговременность |
| `experiment.json` | Схема эксперимента, версии библиотек, ограничения и параметры |
| `pr_curves.png` | Сравнительные PR-кривые |

### Перед научными выводами проверить

1. В `cohort_audit.csv` есть **положительные и отрицательные** примеры из нескольких скважин, причины исключений ожидаемы; число наблюдавшихся переходов разумно по отношению к прежнему аудиту 11 завершённых эпизодов.
2. Никакая оценка не построена по текущему `class`, `state` или будущим измерениям. Признаки — исключительно датчики.
3. В `by_well.csv` улучшение не обусловлено одной скважиной `WELL-00011`.
4. Сравнение AP=0,3243 из предыдущего `oracle_gated` эксперимента с новым AP **напрямую некорректно**: это разные выборки и разные условия применения.
5. Высокое качество на этих данных **не подтверждает эксплуатационную пригодность**: здесь отсутствует представительная длинная история нормальной работы разных скважин.
6. Результаты изучения нескольких моделей на семи ранее исследованных скважинах являются **предварительными**, даже при LOOW.

## 6. Что НЕ изменяем

`ml_agent.py`, `coordinator.py`, `prognostic_agent.py`, `rule_based_agent.py`, `streamlit_app.py`, JSON-правила и прошлые отчёты остаются без изменений. Модель CatBoost не заменяет работающую модель автоматически. Решение о внедрении принимается только после просмотра реального OOF и дополнительных проверок.

Старые БД и Git для этого эксперимента не нужны.
