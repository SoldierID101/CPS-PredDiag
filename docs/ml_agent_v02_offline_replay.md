# ML Agent v0.2 — техническая проверка эквивалентности на реальной телеметрии

**Статус:** исследовательский replay v0.1, 06.11.2026. Не независимая валидация ML-качества.

## Зачем этот эксперимент

Проверяем, что `ShadowMLAgentV02`, получая только **прошлую телеметрию**, вычисляет те же 12 признаков и такую же числовую оценку CatBoost, как исследовательский конвейер 30-минутного прогнозирования DHSV (класс 2). Это интеграционно-техническая проверка; она **не** доказывает качество прогноза на новых скважинах.

**Не изменяются:** `ml_agent.py`, `ml_agent_v02.py`, Coordinator, Streamlit, PostgreSQL и обучающие скрипты. Нет сохранения модели как `pickle/joblib`. Истинные `class`, `state` удаляются до формирования расписания и вызова агента.

## Сценарий

1. Из `outputs/class2_horizons/cohort_features.csv` берётся **только горизонт 30 мин**.
2. Создаётся CatBoost-12 с **теми же параметрами**, что в `experiments/evaluate_class2_alert_policy.py`: 300 деревьев, depth 4, LR 0.03, L2 5, `auto_class_weights=Balanced`, seed 42.
3. Протокол LOOW: полностью исключается `WELL-00012` из обучения. **Никакие дополнительные hard negatives не добавляются** (baseline ratio 0%). Не подбирается новая модель и порог по WELL-00012.
4. Считывается файл `dataset/2/WELL-00012_20170320011000.parquet`, сразу остаются только `timestamp`, `P-MON-CKP`, `P-TPT`, `T-TPT`.
5. Каждые 300 секунд в непрерывном сегменте, начиная с 900-й секунды, вызывается `ShadowMLAgentV02.predict` с ровно 900 прошлыми секундами. Вектор признаков берётся из последних 300 секунд. Без просмотра будущего, `class` или `state`.
6. Для моментов из исходного исследовательского risk set сравниваются `FEATURES` и `model_score` с сохранённым `class2_scores_and_alerts.csv`, фильтр `ratio=0`, `policy=fixed05_1`, `outer_well=12`. В том же режиме сравнивается `alarm_active` (порог 0,5, одно подтверждение).
7. В остальных моментах прогноз возможен, но **нет подтверждённой ретроспективной целевой метки**, пригодной для этой оценки. Такие строки не считаются TP/TN/FP/FN.

## Наблюдения в локальной проверке

Проверка выполнена на реальной телеметрии, ранее извлечённой из предоставленного Parquet-файла WELL-00012, через локальную CSV-копию (в среде проверки отсутствует `pyarrow`). Применялась CatBoost 1.2.8, pandas 2.2.3. У исследователя на Windows используются CatBoost 1.2.10, pandas 3.1.0; их необходимо проверить отдельно.

## Как запустить в Windows

В PowerShell, из `D:\CPS-PredDiag`, после распаковки пакета:

```powershell
python -m unittest discover -s tests -p "test_offline_replay_ml_v02.py" -v
python -m unittest discover -s tests -v
python experiments/offline_replay_ml_v02.py
```

Ожидаемые исходные файлы:

- `dataset/2/WELL-00012_20170320011000.parquet`;
- `outputs/class2_horizons/cohort_features.csv`;
- `outputs/class2_hard_negative_balance/class2_scores_and_alerts.csv`;
- `experiments/evaluate_class2_alert_policy.py`;
- исправленный ранее `ml_agent_v02.py` (TimeFix).

Если файлы лежат в другом месте, укажите пути:

```powershell
python experiments/offline_replay_ml_v02.py --telemetry "dataset/2/WELL-00012_20170320011000.parquet" --cohort "outputs/class2_horizons/cohort_features.csv" --reference "outputs/class2_hard_negative_balance/class2_scores_and_alerts.csv"
```

Нужен `pyarrow` для чтения Parquet; в ранее работающих экспериментах он уже используется. Если отсутствует: `python -m pip install pyarrow`.

Результаты останутся **локально**, внутри `outputs/ml_agent_v02_replay/`:

- `WELL-00012_20170320011000_replay.csv` — по каждому времени: оценка, тревога, флаг сравнимости, расхождения.
- `replay_summary.json` — числа, SHA256 входных файлов, версии Python/pandas/CatBoost, `parity_pass`.

Если разница превышает установленный допуск, скрипт сохраняет отчёт и завершается ошибкой: он **не скрывает несовпадение** и не переключается на другого обученного агента.

## Что этот replay НЕ доказывает

- Прогностическую точность нового агента. Он использует ранее исследованный классификатор.
- Независимую обобщающую способность на unseen WELL: тестовая WELL уже многократно анализировалась при разработке.
- Промышленную частоту ложных тревог, вероятность отказа или пригодность для управления оборудованием.
- Эквивалентность других вариантов (25%, 50% hard negatives, вложенных настроенных политик) — здесь проверен **только baseline ratio 0 / fixed05_1**.

**Следующее действие:** после подтверждения `parity_pass=true` в Windows можно проектировать replay на нескольких файлах и обдумать отдельный протокол для моделей с hard negatives, не выдавая очередные результаты по известным WELL за независимую оценку.
