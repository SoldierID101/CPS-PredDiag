# JSON-конфигурация Rule-Based Agent

**CPS-PredDiag · версия формата 1 · исследовательский прототип**

## Где хранятся правила

- `rules/class2_dhsv.json` — **исполняемая** конфигурация для класса 2.
  Сейчас её статус `draft`, а `rules` — пустой массив: утверждённых порогов нет.
- `docs/diagnostic_rules.md` — научные источники, гипотезы, аудит реальных
  эпизодов и ограничения. **Это не исполняемый файл.**
- `rule_config.py` — загрузчик и проверка структуры JSON.
- `rule_based_agent.py` — существующий исполнитель правил по одному текущему измерению.

Пример текущей конфигурации:

```json
{
  "schema_version": 1,
  "dataset": "Petrobras 3W Dataset v2.0.0",
  "event_class": 2,
  "approval_status": "draft",
  "rules": []
}
```

При пустом списке правил `RuleBasedAgent.evaluate()` возвращает `unknown`, **не** `normal`.

## Как загружать

Из корня проекта:

```python
from rule_config import load_rule_agent

agent = load_rule_agent("rules/class2_dhsv.json", expected_event_class=2)
result = agent.evaluate({"P-PDG": 12000000.0, "P-TPT": 10000000.0})
assert result["status"] == "unknown"  # Пороги ещё не утверждены.
```

Числа здесь — лишь пример входного словаря, **не пороги**, не характеристика
какой-либо скважины и не результаты эксперимента.

## Условия добавления правила в JSON

1. Подтвердить физическую гипотезу и отобрать параметры **на обучающих скважинах**.
2. Провести независимую оценку ложных тревог, обнаружений и заблаговременности.
3. Задокументировать источник, единицу измерения, порог и версию эксперимента в
   `docs/diagnostic_rules.md`.
4. Только после исследовательского утверждения изменить `approval_status`
   на `approved` и добавить элементы в `rules`.

Выполняемое правило должно содержать `id`, `sensor`, `condition`, `threshold`,
`severity`, `unit`, `source`, `message`. Сравнения поддерживаются только
`>`, `>=`, `<`, `<=`; уровни — `warning`, `critical`.

**Важно:** `approval_status: "approved"` — ручное исследовательское разрешение,
**не гарантия научной валидности**. Загрузчик проверяет структуру и наличие
описания источника, но не способен проверить качество самого источника.

Правила по **сочетаниям трендов нескольких датчиков** (`RULE-DHSV-001` и варианты)
пока **не поддерживаются** существующим исполнителем. Добавлять их как
однопороговые правила с выдуманными числами нельзя; сперва нужна независимая
проверка гипотезы, затем отдельная реализация сложных условий.

Загрузчик не использует БД, не читает метки событий для принятия решений,
не генерирует управляющие команды и не влияет на ML Agent.
