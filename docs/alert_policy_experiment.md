# Эксперимент: политика предупреждений CatBoost-12 (30 минут)

**Статус:** предварительный исследовательский эксперимент, версия 0.1.  
**Данные:** Petrobras 3W Dataset v2.0.0, реальные WELL-файлы события класса 2.  
**Постановка:** прогноз наступления класса `2` в следующие 30 минут, без oracle-метки `102` на входе модели.  
**Алгоритм:** CatBoostClassifier, 12 признаков по прошлым 5 минутам, модель не меняется.

## Зачем этот эксперимент

При фиксированном пороге 0.5 CatBoost обнаруживал 9 из 11 эпизодов в последующие 30 минут, но выдавал 85 ложноположительных **окон**. Необходимо проверить, можно ли сократить повторяющиеся предупреждения и улучшить принятие решений, не подгоняя порог по тестовой скважине.

## Как воспроизвести

Сначала должен быть успешно выполнен предыдущий эксперимент:

```powershell
python experiments/compare_class2_horizons.py
```

Затем:

```powershell
python -m unittest discover -s tests -v
python experiments/evaluate_class2_alert_policy.py
```

Входы берутся из `outputs/class2_horizons/cohort_features.csv` и `outputs/class2_horizons/oof_predictions.csv`. Повторно читать ~1.74 ГиБ датасета для этой процедуры не нужно: признаки и внешние OOF-оценки уже вычислены.

## Что делает алгоритм

1. Фиксируем **30 минут** как исследовательский горизонт. Это решение мотивировано предыдущими экспериментами, поэтому итог **не может считаться независимым подтверждением выбора горизонта**.
2. Внешнее разбиение: Leave-One-Well-Out; одна скважина целиком тестовая.
3. На остальных шести скважинах выполняем **внутреннюю Leave-One-Well-Out** проверку, заново обучая CatBoost на пяти скважинах и получая внутренние OOF-оценки на шестой. Внешняя тестовая скважина не участвует ни в одном внутреннем обучении и подборе.
4. Подбираем настройки по заранее определённой сетке порогов `{0.1, 0.2, …, 0.8}` и числа последовательных повышенных оценок `{1, 2}`. Цель: обнаружение не менее 80% завершённых эпизодов **во внутренних OOF-оценках**. Среди достигших цели минимизируем количество *начал предупреждений вне 30-минутного горизонта* на час пригодных отрицательных наблюдений. Если цель недостижима, выбираем максимальное обнаружение и затем минимальное число начал предупреждений.
5. Применяем выбранное правило только к внешним OOF-оценкам соответствующей тестовой скважины. Изменять его по итогам внешнего теста запрещено.
6. Политика опирается только на текущую и предыдущие оценки CatBoost; не получает метки `class`, `state`, `102`, время будущего события и `target`. Разрыв более 5 минут сбрасывает счётчик последовательных оценок.

**Важное уточнение:** правило с `confirmations=2` формирует начало нового предупреждения только на второй последовательной оценке, превысившей выбранный порог. При продолжающемся превышении сигнал остаётся **активным**, но новая тревога не создаётся каждую пятиминутку.

## Проверенные результаты на сохранённых CSV

Выполнено 07 внешних и 42 внутренних разбиения (CatBoost v1.2.8; исходные внешние OOF-оценки с пользовательского запуска CatBoost v1.2.10). Точные выборы могут слегка отличаться при изменении версий библиотек.

| Метрика | Фиксированное правило 0.5, 1 оценка | Вложенная настройка по обучающим скважинам |
|---|---:|---:|
| Precision окон | 0.3511 | **0.3858** |
| Recall окон | 0.6970 | **0.7424** |
| F1 окон | 0.4670 | **0.5078** |
| Ложноположительных окон | 85 | **78** |
| Всего начал предупреждений | 21 | **15** |
| Начал вне 30-минутного горизонта | 17 | **12** |
| Эпизодов с активным предупреждением в пределах горизонта | 9/11 | **9/11** |
| Эпизодов с *новой* тревогой впервые в пределах горизонта | 3/11 | **3/11** |
| AP исходных оценок | 0.2939 | 0.2939 (не изменяется постобработкой) |

В семи внешних разбиениях внутренний алгоритм выбрал **две последовательные оценки** и пороги от 0.3 до 0.5 (зависит от удержанной скважины).

**Интерпретация:** мы сократили число отдельных тревог и улучшили оконный F1 без снижения числа эпизодов с активным сигналом. Однако большинство обнаруженных эпизодов имели **начало сигнала раньше 30-минутного горизонта**. Например, на WELL-00002 первая тревога возникла примерно за 38.4 минуты до события. Поэтому 9/11 и 3/11 описывают **разные свойства системы** и не должны подменять друг друга.

## Файлы результатов

- `comparison.csv` — сравнение политики с прежним правилом 0.5;
- `policy_by_well.csv` — выбранный порог и подтверждение в каждом внешнем фолде;
- `inner_selection_grid.csv` — все кандидаты, оцененные только на внутренних обучающих скважинах;

## Ограничения исследования

1. **Нельзя называть это независимым окончательным тестом.** Горизонт, состав признаков и модель уже исследовались на этих семи скважинах. Вложенный подбор защищает только от новой утечки *на этапе выбора порога и подтверждений*.
2. Метки `class` участвуют при формировании целей и исключении уже наступивших событий. Это ретроспективная оценка, не полное воспроизведение эксплуатационного потока.
3. Данные состоят из **специально отобранных эпизодов класса 2**, а не многомесячной нормальной эксплуатации. Показатель тревог на час отрицательных *оцениваемых* окон не равен промышленной частоте ложных тревог.
4. Предупреждение более чем за 30 минут до реального события формально является отрицательным **для данной целевой переменной**. Оно не обязательно физически ложное, но не может автоматически считаться верным 30-минутным прогнозом.
5. Всего **11 завершённых событий на 7 скважинах**; статистическая неопределённость высока.
6. Выход CatBoost не калиброван; никакие оценки нельзя трактовать как достоверную вероятность поломки.
7. По результатам этого эксперимента **не заменяем** модель в `ml_agent.py` и не формируем управляющие действия.
