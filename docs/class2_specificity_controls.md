# CPS-PredDiag — стресс-тест специфичности класса 2 (v0.1)

**Статус:** экспериментальная проверка, не промышленная валидация.  
**Модель:** CatBoost-12, горизонт 30 минут.  
**Обучение:** прежняя размеченная когорта класса 2 (`outputs/class2_horizons/cohort_features.csv`).  
**Правила тревоги:** настройки из `outputs/class2_alert_policy/policy_by_well.csv`.

## Исследовательский вопрос

Когда CatBoost обучен прогнозировать непредусмотренное закрытие DHSV (класс 2),
сколько **ложных тревог о классе 2** он выдаёт на реальных записях, где по
доступной разметке этот класс не встречается?

Предыдущая оценка 9/11 обнаруженных событий и F1 = 0,508 относится только к
специально отобранным файлам класса 2. Она **не** характеризует частоту
тревог в других режимах эксплуатации.

## Источники контрольных данных

- `dataset/0/WELL-*.parquet`: реально зарегистрированные файлы нормальной работы.
- `dataset/{1,3,4,5,6,7,8,9}/WELL-*.parquet`: другие типы событий,
  в том числе нормальные интервалы **внутри** таких файлов.
- `SIMULATED` и `DRAWN` файлы намеренно исключаются.
- Папка класса `2` намеренно не используется в контрольной выборке.

По умолчанию детерминированно выбирается не более **двух файлов на сочетание
(класс, скважина)**, упорядоченных по SHA256 относительного пути. Отбор
не использует значения датчиков, будущие события или предсказания.
Это небольшая, воспроизводимая подвыборка, не весь Petrobras 3W.

## Процедура

1. Восстановить обучающую выборку 30 минут, 12 ранее утверждённых в
   исследовании признаков CatBoost и те же гиперпараметры (300 итераций).
2. Для скважин, представленных в обучающей когорте класса 2,
   обучить модель **без всех записей соответствующей скважины** (LOOW).
3. Для новых скважин обучить отдельную модель на всех семи скважинах класса 2.
   Эта группа обозначается `new_well_fullfit` и **не объединяется** с LOOW.
4. В контрольных файлах рассматривать диагностические моменты через 5 минут,
   после 15 минут непрерывной доступной истории. Признаки извлекать **только из прошлого**.
5. Оставить для оценки только моменты, когда известны текущая разметка и
   **все следующие 30 минут**, без класса 2/102. Пробелы в разметке,
   разрывы и окончание файла = исключённые/цензурированные моменты,
   **не «нормальное состояние»**. Исключения записываются в `file_audit.csv`.
6. Считать ложные тревоги о классе 2 отдельно на нормальных файлах,
   нормальной части файлов других событий, переходных фазах и уже
   наблюдаемых событиях других классов.
7. Сравнить три правила: `fixed05_1` (порог 0,5, одно окно),
   `fixed05_2` (порог 0,5, два последовательных окна),
   `nested` (порог и подтверждение из прежнего вложенного эксперимента).
   Для ранее невиденных скважин вместо переноса адаптированного порога
   используется явно помеченное фиксированное правило 0,5/2.

**Ключевой момент:** `class` используется исключительно для проверки того,
что оценка относится к известному отрицательному исходу; `class`, `state`,
идентификатор скважины и будущие измерения **не входят в признаки CatBoost**.

## Что означает метрика

`false_alarm_starts` = число начал отдельной тревоги, а не количество
соседних окон, где предупреждение активно.

`eligible_negative_hours = число пригодных отрицательных решений × 5 / 60`.

`starts_per_eligible_negative_hour` — **не производственная FAR**: отдельные
окна могут выпадать из-за цензуры, качество исходных меток ограничено, а
файлы выбраны из конкретных категорий. В частности, сигнал на фоне другого
опасного события «ложный» только по **типу DHSV**, но не обязательно
бесполезен как общее предупреждение о проблеме.

В этом эксперименте *нет положительных событий класса 2*, поэтому **не
вычисляем Precision, Recall, F1 и долю обнаруженных эпизодов**. Их результаты
из прежнего исследования не следует складывать с текущими метриками.

## Запуск

Из корня проекта в активной `.venv`:

```powershell
python -m unittest discover -s tests -v
python experiments/evaluate_class2_controls.py
```

Для первого короткого прогона можно отдельно проверить только нормальные
файлы (это **другая, более узкая выборка**):

```powershell
python experiments/evaluate_class2_controls.py --classes 0 --per-class-well 1 --output outputs/class2_specificity_normal_smoke
```

По умолчанию скрипт использует весь список классов контроля и два файла на
(класс, скважина). Для более широкого исследования число можно увеличить,
**не выбирая по результатам, какие именно файлы сохранять**.

## Критерий продолжения

Если класс 2 часто предсказывается на нормальных данных или других событиях,
не менять порог по этим же тестовым данным и не объявлять модель успешной.
Сначала формулируется новая гипотеза (признаки, обучение на отрицательных
эпизодах, калибровка или специфика классов), затем проводится **новое
разделение для подбора и оценки**.

Для последующего промышленно-ориентированного отчёта нужны более
репрезентативные интервалы нормальной эксплуатации, полная хронология
предсказаний, учёт пропусков и доверительные интервалы по скважинам/эпизодам.

**Из существующего приложения ничего не меняем.** Этот эксперимент не
подключает CatBoost к ML Agent/Streamlit и не возвращает старую БД.
