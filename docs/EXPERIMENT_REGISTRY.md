# CPS-PredDiag — единый реестр экспериментов

**Актуализировано:** 19 ноября 2026.
**Назначение:** не путать прогностическое качество, техническую воспроизводимость и предварительный подбор настроек. Реестр не заменяет исходные CSV/JSON и версию Git.
**Правило доказательств:** численный результат без оригинального файла-источника не считается вновь проверенным. В этом реестре часть цифр сверена по предоставленным файлам/отчётам, часть оставлена как результаты предыдущих запусков пользователя и помечена отдельно.

## Условные уровни подтверждения

- **R — реальный исследовательский результат:** получен на Petrobras; не является независимым финальным тестом, если скважины уже участвовали в разработке.
- **P — техническая эквивалентность:** показано совпадение кода или прогнозов с архивом; сама модель от этого точнее не становится.
- **S — синтетический тест:** проверяет контракт или алгоритм на искусственных данных; напечатанные AP=1.0/F1=1.0 не относятся к реальным скважинам.
- **E — эксперимент подготовлен / предварительный результат:** не подтверждён завершённым прогоном на пользовательском ПК.

## Актуальная интерпретация

1. **Надёжнее всего подтверждено инженерное свойство:** `ShadowMLAgentV02` воспроизводит ранее изученную CatBoost-12 на 503 архивных моментах, но не доказано улучшение качества событий.
2. **Выбор лучшего алгоритма не завершён.** Logistic Regression лидирует по AP в E10, но её специфичность к другим классам неисправностей пока не подтверждена и после подбора политики уменьшается event recall.
3. **Недопустимо смешивать E02, E06 и E10:** там разные конфигурации CatBoost, иногда разные методы выбора порога/доли контрольных окон.
4. Оконные FP, число начала тревог, доля времени тревоги и event recall — **разные метрики**.
5. Конечная независимая валидация на ранее не использованных скважинах/событиях ещё не представлена.

## Какие файлы держать как исходные доказательства

- `docs/2026-11-05_experiment_summary.md`, `docs/hard_negative_balance.md`, `docs/class2_horizon_comparison.md` — существующие ранее отслеживаемые исследовательские описания; **сверить содержание и точные ссылки на outputs**, прежде чем считать их исчерпывающими.
- `outputs/ml_agent_v02_replay_all_wells/all_wells_replay_summary.json`, `file_parity.csv`, `well_parity.csv` — названия результатов пользовательского запуска E09; папка не должна автоматически добавляться в Git.
- `outputs/class2_model_benchmark/model_comparison.csv`, `by_well.csv`, `oof_predictions.csv`, `benchmark_manifest.json` — результаты E10, пользователь прислал копии.
- `outputs/class2_nested_alert_benchmark/` и `outputs/class2_control_specificity_benchmark/` — **ожидаемые** каталоги результатов E11/E12, не считать заполненными без проверки.

## Как регистрировать следующий эксперимент

Для нового запуска добавлять **одну строку** и указывать: идентификатор, файл кода/коммит Git, SHA256 когорты и источника, целевую переменную/горизонт, split по WELL, модель и гиперпараметры, политику тревоги (если есть), метрики на окнах/событиях/контролях, источник цифр, уровень R/P/S/E, ограничения. Никогда не записывать результат только по stdout синтетического теста как реальный результат Petrobras.

**Статус Git:** перечисленные экспериментальные файлы не обязательно отслеживаются Git; последний предоставленный `git status --short` показал часть из них как `??`. Не выдавать это за проверенный статус после 19.11.2026.
